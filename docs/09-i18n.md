# Internationalization

## Supported Languages

- English (`en`)
- Vietnamese (`vi`)

Current initial language is Vietnamese. The renderer first reads the application
language key from local storage and otherwise uses the Electron desktop preference.
Changes update document language and the desktop preference.

## Source

Current UI translations live in `frontend/lib/i18n.tsx`. Known backend error
messages are mapped to localized frontend copy. Permission and role identifiers
remain stable English technical keys.

## Rules

- Every page, modal, empty state, validation message, notification, startup stage,
  shutdown dialog, update surface, and hardware error must follow the selected language.
- Vietnamese text uses proper diacritics and UTF-8.
- Do not embed user-facing text inside business logic when it can use an i18n key.
- Backend codes and contracts remain language-neutral where possible.
- English fallback is allowed only when a translation key is genuinely missing;
  new work must add both languages before completion.

## Formatting

- Business timezone is GMT+7, preferably identified as `Asia/Ho_Chi_Minh`.
- Default display direction is day/month/year with 24-hour time.
- Number formatting follows the active locale; Vietnamese presentation uses
  period grouping and comma decimal conventions where applicable.
- Fixed `vi-VN` formatting inside an English screen should be treated as an i18n defect unless the value is explicitly Vietnamese-only.

## Persistence

Application-owned language keys may be cleared during logout only when the
approved logout policy requires it. Never clear all origin storage. Desktop
preference remains available for startup UI before the renderer is authenticated.

## Review Gate

For new UI:

- inspect both languages at the primary 1280 x 1024 viewport;
- verify diacritics in source and rendered output;
- check long labels, table headers, dialogs, and virtual keyboard layouts;
- verify errors and status do not expose unlocalized backend internals.
